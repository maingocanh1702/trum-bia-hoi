## 2. Principles (unchanged from v2, restated for master)

1. **Understand before editing** — `/how` names owner module, commands, events, world fields,
   the tests that already pin the behaviour, and whether the change is engine / server / web-local /
   web-remote. Prefer extending the owner module over a sibling.
2. **Two tiers, two "production paths"** — engine tier: `game.command()` + `advance()` *is* the
   production path (local mode calls it through `dispatch()`; the server calls it per request).
   UI tier: through the DOM only. Remote-mode UI proof additionally needs the isolated API
   (`playwright.remote.config.ts`) — never a mocked `/api`.
3. **Read-only bridge** — observe, never mutate; deterministic setup stays "fixture save".
4. **Behaviour map, not source map** — feature files name what the player/sim observes and cite
   the existing test names as proof; they never restate `engine.ts`.
5. **Binding checks are verification** — `npm run verify` and `check:assets` are the static tier;
   `doctor` refuses PASS when they are red.

## 6. Wave V2 — snapshot + read-only bridge (both modes)

`packages/engine/src/snapshot.ts` — pure, versioned (`schema: 1`), JSON-safe, no Pixi/functions:
`configVersion, now, phase, seed?, logLength, shift{elapsed,duration,weather,rush,stats},
tables[{id,state,level,capacity,groupId,orderId,orderState,itemsReady,itemsTotal}], queue[],
glasses{by state}, keg, inventory, equipment, economy{coins,reputation,seasonEarned,lifetimeEarned,serves},
location, lease, staminaMs, completedShifts, quests/attendance counters, signboard/flyer/dog levels`.
Unit test: serialisable, independent of `world` identity.

`apps/web/src/verify/bridge.ts` — installed from `main.tsx` only when `import.meta.env.DEV ||
import.meta.env.VITE_TBH_VERIFY === '1'` (set by the Playwright web servers); absent from prod build.

```ts
window.__TBH_VERIFY__ = {
  version(): { schema: 1; commit; worktree; mode: 'local'|'remote'; startedAt; configVersion },
  snapshot(): VerificationSnapshot | null,   // local: snapshot(game); remote: derived from the last server snapshot (WorldView)
  events(since?): DomainEvent[] | PresentationEvent[],   // local: world.events; remote: presentation cursor
  connection(): Connection | 'local',
  journal(): { nextSeq, pending, cursor } | null,        // remote outbox counters, read-only
  settings(): Settings
}
```
No key may call `command`, `advance`, `persist`, `replaceSave`, or write storage; a unit test pins
the key set. `commit`/`worktree` come from `define` in `vite.config.ts`.

Acceptance: `page.evaluate(() => __TBH_VERIFY__.snapshot())` works under both `playwright.config.ts`
(local) and `playwright.remote.config.ts` (remote); prod bundle has no `__TBH_VERIFY__` string.

## 7. Wave V3 — doctor, ports, evidence helpers

- `scripts/verify/port.ts`: main workspace keeps today's ports; a worktree (`.git` is a file) gets
  `base = 5200 + hash(worktree) % 300` and derives dev/e2e/api/playable ports from it. All five
  Playwright configs and `dev`/`dev:server` read `TBH_PORT_BASE` when set (default = today's values,
  so nothing changes for the main workspace).
- `scripts/verify/doctor.ts`:
  ```text
  repo      ✓ trum-bia-hoi root · branch/worktree/HEAD · origin fetched
  deps      ✓ node ≥ 22.12 · node_modules · playwright browsers (UI tier)
  binding   ✓ check:config · check:i18n · engine purity (no react/dom/window/Date.now/Math.random in packages/engine/src, rng.ts excepted)
            ✓ sims k band — only when packages/engine or economy JSON changed vs base
  map       ✓ feature-map coverage: every command/event cited; every test/spec file cited
  server    ✓ web reachable on the worktree port · API reachable when mode=remote
  bridge    ✓ __TBH_VERIFY__ present · version().commit == HEAD (else ✗ STALE BUILD) · worktree matches (else ✗ WRONG INSTANCE)
  console   ✓ no error-level messages at boot (known: admin-api.ts:68 pattern warning is listed, not hidden)
  ```
  `--engine-only` skips server/bridge/console. Output saved to `artifacts/verification/<branch>/doctor.txt`.
- `apps/web/test/tbh-fixture.ts`: `tbh.snapshot()`, `tbh.waitForEvent(type,{since})`, `tbh.shot(name)`,
  `tbh.consoleErrors()`, `tbh.evidence()` writing to `artifacts/verification/<branch>/`. Existing specs
  are not rewritten; new specs use it.

Acceptance: two worktrees run `test:e2e` simultaneously without port collision; doctor detects a
stale bundle and a wrong worktree; PASS is refused on a red doctor.
